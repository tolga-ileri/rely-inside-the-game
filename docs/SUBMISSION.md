## Elevator pitch (about 130 words)

Football produces thousands of events per match, but people want one answer: why did the match change? Rely Match Brain
is an event-driven reasoning system that watches a live event stream and keeps an exact match state. Deterministic rules
detect real turning points, such as a substitution that moves the attack to the right, a red card, or a late surge. A
team of agents then explains them: an Event Analyst, a Tactical Analyst, an Evidence Verifier that re-checks every
number, and a Narrative agent built on Azure AI Foundry. Coaches, analysts, broadcasters and fans each get their own
view of the same evidence, in English, Turkish or Spanish. Every claim links to event ids and timestamps, and the system
moves from insight to decision: it proposes a tactical response with an animated 4-3-3 → 3-2-5 preview. All data is
synthetic.

## Description

Rely Match Brain replays a synthetic match event by event. The Match State engine recomputes score, possession,
final-third entries by channel, pressures, recoveries and momentum from the events received so far, with rolling
5- and 10-minute windows. Tests prove it never sees the future. A deterministic detector flags turning points with
before and after windows, trigger events, evidence and confidence. Agents turn those facts into typed Observations,
Patterns, Findings, Hypotheses, Recommendations and Risks. A verifier checks them, and the narrative is generated for
each persona and language. The UI shows Before / Trigger / After, an evidence panel, a sequence viewer, an agent trace,
recaps and a tactical response.

## Problem

Match data is plentiful, but understanding is not. Analysts spend hours connecting events to causes. Generic AI summaries
can invent numbers, players and causes, which ruins trust for coaches and broadcasters.

## Solution

Separate facts from language. Rules and the state engine decide what happened; AI only explains it, under strict
grounding. Facts are computed once and stay the same whatever the language or persona. If the AI fails or invents
something, a grounded template takes over, so the system still explains the moment.

## Microsoft technology

- **Azure AI Foundry** model inference (`azure-ai-inference` SDK): Narrative agent with JSON outputs and streaming
  support, behind a provider abstraction (`AI_PROVIDER=microsoft_foundry`). Responses are cached by state hash,
  persona, locale and model.
- **Azure Container Apps**, **Azure Container Registry**, **Log Analytics**: Bicep template and deploy script with
  liveness, readiness and startup probes.
- **GitHub Actions**: tests, lint, typecheck, build, AI eval smoke, Docker builds, gitleaks secret scan.

Honesty note: Foundry integration is implemented and tested with fake clients. No live Foundry run or Azure deployment
has happened at the time of writing. The demo runs on deterministic templates (`AI_PROVIDER=none`).

## Agentic design

An orchestrator runs Match State → Turning-Point Detector → Event Analyst → Tactical Analyst → Evidence Verifier →
Narrative over one explicit typed shared state. Each agent has a single role and its own failure boundary. If the
Tactical agent fails, the Event output remains; if the Narrative agent fails, the structured intelligence remains and
the UI says "AI explanation unavailable". The verifier enforces numeric grounding, entity validation and evidence
coverage, and gives the Narrative agent one chance to regenerate before falling back. An Agent Trace shows per-agent
latency, provider, model, fallback and coverage, without prompts or secrets.

## Enterprise readiness

Typed schemas (pydantic and TypeScript), structured JSON logs with latencies, `/health` and `/ready` endpoints,
containerised services with health checks, infrastructure as code, a secret-free repository (`.env` ignored, gitleaks
in CI), an offline eval suite (100/100, including adversarial cases), and deterministic, reproducible data.

## Synthetic data compliance

All clubs (Harbour City FC, Westvale Athletic, Kingsmere Rovers, Elmstead Town), players and events are fictional and
generated by a seeded simulator. No real Premier League data, club logos or trademarks are used. The hackathon is
referenced by name only. The UI permanently shows **SYNTHETIC FOOTBALL-REALISTIC DATA**.

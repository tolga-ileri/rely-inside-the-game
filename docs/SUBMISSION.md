## Elevator pitch

<!-- pitch:start -->
Football changes before the scoreboard does. Rely Match Brain watches a stream of synthetic, football-realistic match
events and keeps a real-time match state built only from what has happened so far. Deterministic rules detect turning
points, such as a substitution that moves the attack to the right. Specialised agents then explain them: an Event
Analyst, a Tactical Analyst, an Evidence Verifier that recomputes every number, and a Narrative agent. The same verified
evidence becomes a decision for coaches, an analysis for analysts, a story for broadcasters and a plain explanation for
fans, in English, Turkish or Spanish. Rely also proposes a tactical response and states its trade-off. The architecture
is ready for Microsoft Foundry and Azure Container Apps; the submitted demo runs on its local fallback.
<!-- pitch:end -->

## Project description

<!-- description:start -->
**Problem.** A football match produces thousands of events, but coaches, analysts, broadcasters and fans want one
answer: why did the match change? Generic AI summaries can invent numbers, players and causes, and once that happens
nobody can trust them.

**Solution.** Rely Match Brain separates facts from language. Deterministic analytics decide what happened; agents
explain it under strict grounding; every claim links back to events.

**How it works.** A synthetic match is replayed event by event. The match state engine recomputes score, pass share,
progressive actions by channel, final-third entries, pressures and momentum from the events received so far, with
rolling windows; tests prove it never sees the future. A rule-based detector flags turning points with a trigger,
before and after windows, evidence and confidence. In the demo, a 56th-minute substitution is detected at 60:03: the
right channel's share of progressive actions rises from 25% to 71%.

**Agent architecture.** An orchestrator passes one typed shared state through four specialised agents. The Event
Analyst produces observations, the Tactical Analyst interprets them, the Evidence Verifier recomputes every metric and
rejects unknown players, invented scores, future events and definitive causal claims, and the Narrative agent writes
for the chosen persona and language. Each agent has its own failure boundary, and an Agent Trace shows status,
latency and provider for every step.

**Explainability.** Before, Trigger and After are shown side by side with event ids and time windows. Evidence coverage
is honest (20 supported, 2 unverifiable causal hypotheses, 0 rejected), and persona or language changes never alter a
fact.

**Microsoft stack.** A Microsoft Foundry provider for the Narrative agent, with structured output, streaming, caching
and a grounded fallback; containers and a Bicep template for Azure Container Apps; GitHub Actions for tests, evals,
Docker builds and secret scanning. No Foundry credentials were available during final validation, so the demo uses the
local fallback, and nothing has been deployed to Azure.

**Impact.** The same engine serves a coach deciding a change, an analyst checking evidence, a broadcaster preparing a
talking point and a fan following the game, with every claim traceable to the events behind it.

## Judging criteria

**Technological Implementation.** A deterministic event engine with rolling windows and rule-based turning-point
detection, typed schemas end to end, and an orchestrated agent pipeline. 94 backend tests, 11 frontend tests and a
100-case offline AI evaluation; CI also runs lint, typecheck, build, Docker builds and a secret scan.

**Agentic Design & Innovation.** Four agents with distinct jobs share one typed match state and hand off structured
claims, not prose. The verifier can reject another agent's output, and each agent fails independently without taking
the others down. The innovation is the order: facts first, verification second, language last.

**Real-World Impact.** One verified finding becomes a decision for a coach, evidence for an analyst, a talking point
for a broadcaster and a plain explanation for a fan. Tactical responses state their trade-off, so staff can judge them
rather than follow them blindly.

**UX & Presentation.** One screen: scoreboard, pitch with numbered sequences, a quiet intelligence feed and a momentum
timeline. Why, Evidence, Agent Trace, Tactical Response and Recap open in a side drawer. Persona and language switch
instantly without recomputing facts.

**Challenge Adherence.** Built only on synthetic, football-realistic event data with fictional clubs, and labelled as
such on every screen. It delivers the requested capabilities: explainable match intelligence, real-time narratives,
automated recaps and personalised experiences.

## Why this is more than match summarisation

A summariser turns a finished match into text. Rely Match Brain reasons forward through a match as it happens:

**events → deterministic intelligence → evidence verification → multi-agent reasoning → personalised narrative → tactical action**

Facts are computed before any language model is involved, they are checked before anything is said about them, and
the output ends in a decision with its trade-off, not a paragraph.

## Multi-agent design

| Agent | Input | Output | Handoff |
|---|---|---|---|
| Event Analyst | Match state, events up to now | Observations: metrics, sequences, anomalies | Tactical Analyst |
| Tactical Analyst | Observations, turning points | Findings, hypotheses, recommendations, risks | Evidence Verifier |
| Evidence Verifier | Every claim plus the shared state | Supported, unverifiable or rejected per claim; coverage | Narrative agent |
| Narrative agent | Verified claims, persona, locale | Headline, explanation, bullets | UI |

- **Shared match state:** one typed object every agent reads; nothing is passed as free text.
- **Structured handoffs:** typed claims with event ids, metrics and windows.
- **Failure recovery:** if the Tactical Analyst fails, Event Analyst output remains; if the Narrative agent fails, the
  structured intelligence remains and the UI says the explanation is unavailable; a model timeout falls back to a
  grounded template. All of this is covered by the evaluation suite.

These are not sequential calls to one model. Three of the four agents are deterministic code, and the Verifier can
overrule the others.

## Enterprise readiness

- Typed contracts (pydantic and TypeScript) for events, state, claims, moments and traces
- Deterministic core: the same events always give the same facts
- Evidence traceability: event ids, timestamps and windows behind every number
- Fallback: grounded templates whenever AI is unavailable or ungrounded
- Auditability: Agent Trace and structured JSON logs with per-stage latency
- Containerised API and web app with `/health` and `/ready`
- CI: tests, lint, typecheck, build, AI eval smoke, Docker builds and gitleaks

Deployment-ready for Azure Container Apps; not deployed.

## Microsoft Foundry

Rely includes a Microsoft Foundry provider and setup path; the submitted demo uses its deterministic local fallback
because no Foundry credentials were available during final validation.

The provider uses the `azure-ai-inference` SDK with JSON output, streaming and a response cache, and every Foundry
answer must pass the same grounding checks as any other text. Activation and verification steps:
[FOUNDRY_SETUP.md](FOUNDRY_SETUP.md). Post-hackathon improvement: the provider currently exposes generic
`complete_json` and `stream_text`; domain methods such as `generate_narrative` and `generate_recap` would make the
contract clearer.

## Synthetic data compliance

All clubs (Harbour City FC, Westvale Athletic, Kingsmere Rovers, Elmstead Town), players and events are fictional and
generated by a seeded simulator. No real Premier League data, club logos, broadcast footage or music is used. The
hackathon is referenced by name only, and the UI permanently shows **SYNTHETIC FOOTBALL-REALISTIC DATA**.
